Getting started

This page walks you from a fresh download to a scene that plays. You do not need a C++ compiler or CMake to use the editor or ship a game. Those are only required when you want to write C++ scripts, and you set them once.

The short version

Extract vace_engine_windows_stable_v0.1.zip, run build\windows-mingw-debug\projectmanager\VACE_ProjectManager.exe, create a project, double-click to open it in the editor, create a scene, add nodes, press Play.

Step 1: extract the release

Download vace_engine_windows_stable_v0.1.zip and extract it to a folder you can write to. Do not run the editor from inside the zip. The extracted folder contains the runtime, the engine libraries, the editor, and the Project Manager:

vace_engine_windows_stable_v0.1/ 
vace_engine_windows_stable_v0.1/
├── build/
│   └── windows-mingw-debug/
│       └── projectmanager/
│           └── VACE_ProjectManager.exe    ← start here
└── docs/             this documentation

Your projects live outside this folder. The extracted release is the engine. Keep it somewhere stable (for example C:\VACE\) and create projects wherever you keep code.

Step 2: run the Project Manager

Launch the Project Manager from:

path 
build\windows-mingw-debug\projectmanager\VACE_ProjectManager.exe

This is the first window you see, and it is where you create and open projects. There is no separate launcher.

If this is your first launch, the list is empty. That is expected. The next step creates your first project.

Step 3: create a project

Choose New Project. You'll be asked for four things:

  • Name: shown in the editor title bar and used as the project folder name
  • Type: 2D or 3D. This sets the default scene and node mode for the project
  • Path: the parent folder for the new project
  • Add .gitignore: a checkbox. Leave it on if you keep the project in git, off otherwise

When you confirm, VACE creates the project folder and its starter files. No build runs at this point, and no compiler is needed.

Step 4: open the project in the editor

In the Project Manager, double-click your project in the list. The editor opens with that project loaded.

If you need to create another project later, you can return to the Project Manager from inside the editor at any time. Project creation is a Project Manager action, not an editor one.

Step 5: create your first scene

A new project opens to a cue telling you to create a scene. The scene tree and viewport stay empty until you do.

Use the scene menu (or the prompt shown in the viewport) to create a new scene. Once the scene exists, the editor shows the empty scene tree and you can start adding nodes. Save the scene when prompted.

Step 6: add your first nodes

Add nodes from the plus button at the top of the hierarchy panel. Clicking it opens a menu split into Node 3D and Node 2D. Pick whichever matches your project type (a 3D project starts with 3D nodes, a 2D project with 2D nodes, but either list is available):

  • Node 3D: meshes, cameras, lights, and other 3D scene objects
  • Node 2D: sprites, 2D cameras, and other 2D scene objects

Select a node after adding it and use the inspector on the right to change its name, transform, and components.

No camera is fine on Play

If the scene has no camera node when you press Play, VACE uses the editor camera. You only need to add a camera to the scene if the game itself needs a specific view.

Step 7: write your first script (optional)

C++ scripting is optional. Everything above works without a compiler. You only need a toolchain when you want to attach a script to a node.

To add a script, use the inspector on a selected node. The inspector has controls to create a new script or attach an existing one. Both flows stay in the editor; you do not need to leave it to make a script.

When you create a script, VACE writes a .cpp into the project's scripts folder. Here is what a minimal script looks like:

Spinner.cpp 
#include "VACE/Scripting/Script.hpp"

class Spinner : public VACE::Script
{
public:
    void OnUpdate(float dt) override
    {
        SetRotation2D(GetRotation2D() + glm::radians(90.0f) * dt);
    }
};

VACE_REGISTER_SCRIPT(Spinner)

The full scripting surface, from input to physics to JSON save data, is in the Script API reference.

Step 8: set the toolchain (only for C++ scripting)

The first time you write or attach a C++ script, VACE needs to know where your compiler and CMake are. Open the Project Manager's Settings tab and fill in:

  • CMake path: full path to cmake.exe
  • Compiler: MinGW-w64
  • Compiler path: path to the toolchain, if not auto-detected

You only do this once per machine. After the toolchain is set, you never need to configure it again unless you change compilers or move the install.

Shipping does not need a compiler

The toolchain is only used to build script .dll files. Building and shipping a game does not require a compiler to be installed on the player's machine. If a project has no scripts, it needs no toolchain at all.

Step 9: press Play

Press the Play button. VACE automatically builds any script DLLs that are out of date, then runs the scene with the editor attached. You'll see script logs in the console, and changes you make in the inspector while playing are applied live. Press Stop to return the scene to its pre-play state.

You have a running scene

From here, the editor walkthrough covers the panels in depth, and the scripting reference covers the full API. If you get stuck, the Contact page lists every way to reach the developer.

A note on inspector fields

VACE_FIELD() is still under active development. Fields marked with it currently show up in the editor inspector and can be edited there, but editing them in the inspector does not yet change the value the running script sees. Until this is finished, treat inspector fields as documentation for now, and set default values directly in the class body.

This is a known limitation and will change in a future release. The rest of the scripting API works as documented.

Common first-run issues

No scene appears when I open the project

That is the expected first state. The editor shows a prompt to create a scene. Create one, save it, then add nodes.

Play does nothing visible

Either the scene has no camera and the editor camera is pointed away from the action, or there are no visible nodes yet. Add a mesh or sprite near the origin and try Play again.

Scripts fail to build

The most common cause is a missing or mismatched toolchain. Open Project Manager > Settings and re-check the CMake and compiler paths. If the project has no scripts, you can ignore this entirely.

Editor crashes on launch

Check that your GPU reports OpenGL 4.3 support. The renderer requires it. If your GPU supports 4.3, update your graphics driver and try again.
