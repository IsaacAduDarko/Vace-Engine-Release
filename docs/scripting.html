Script API reference

The C++ scripting interface for VACE. Scripts subclass VACE::Script, compile into a .dll, and attach to scene nodes. Everything the engine exposes to a script is documented here. Types, enums, and the low-level ABI are on the ABI and types page.

Press / to search this page

The search box at the top of the page filters the methods and sections on this page as you type. Use it to jump to a method by name, or to filter to a single API area (for example type raycast or audio).

Introduction

The VACE::Script base class is the C++ interface used to write gameplay scripts that run inside the VACE runtime. A script is compiled into a .dll, registered with VACE_REGISTER_SCRIPT, and attached to a scene node (or to the scene itself).

All engine calls go through a versioned function-pointer table, VACE_ScriptContext, which the runtime installs before OnCreate fires. Everything documented on this page is a thin inline wrapper over that table.

Minimal script

Spinner.cpp 
#include "VACE/Scripting/Script.hpp"

class Spinner : public VACE::Script
{
public:
    void OnUpdate(float dt) override
    {
        SetRotation2D(GetRotation2D() + glm::radians(90.0f) * dt);
    }
};

VACE_REGISTER_SCRIPT(Spinner)

Quick start

  1. In the editor, select a node and use the inspector to create a new script, or attach an existing one.
  2. Subclass VACE::Script in the generated .cpp file.
  3. Override OnCreate, OnUpdate, or OnDestroy as needed.
  4. End the file with VACE_REGISTER_SCRIPT(ClassName). This emits the exported ABI entry points.
  5. Press Play. VACE builds any out-of-date script DLLs before the scene runs.

Registration and lifecycle

VACE_REGISTER_SCRIPT(ClassName) exports the C entry points the runtime uses to create, drive, and destroy instances:

void* vace_script_create(const VACE_ScriptContext* ctx) void vace_script_destroy(void* p) void vace_script_create_hook(void* p) void vace_script_destroy_hook(void* p) void vace_script_update(void* p, float dt) std::uint32_t vace_script_abi()

Overridable lifecycle hooks

OnCreatevirtual

void OnCreate()

Called once, right after the script instance is constructed and its ABI context is installed. Inspector field values have already been applied. Use this to cache node IDs and set up state.

OnUpdatevirtual

void OnUpdate(float dt)

Called every frame while the script is active. dt is the elapsed seconds since the previous frame, so it is frame-rate independent.

OnDestroyvirtual

void OnDestroy()

Called once before the instance is freed. Release any non-trivial state.

GetFieldsvirtual

const std::vector<ScriptFieldDesc>& GetFields() const

Optional. Return the reflection descriptors the editor uses to display the script's fields. The default returns an empty list.

Inspector fields

Prefix a public member with VACE_FIELD() to make it show up in the editor's inspector. Supported types: float, double, int, bool, glm::vec2, glm::vec3, Vec3, std::string.

Player.cpp 
class Player : public VACE::Script
{
public:
    VACE_FIELD()
    float moveSpeed = 5.0f;

    VACE_FIELD()
    int maxHealth = 100;

    VACE_FIELD()
    bool invulnerable = false;

    VACE_FIELD()
    glm::vec3 spawnOffset{ 0.0f, 1.0f, 0.0f };

    VACE_FIELD()
    std::string greeting = "Hello";

private:
    int m_health = 100;   // not exposed, private state
};
Inspector fields are still under development

VACE_FIELD() members currently show up in the inspector and can be edited there, but editing them does not yet change the value the running script sees. Until this is finished, set default values directly in the class body and treat the inspector field as documentation. This is a known limitation and will change in a future release.

Rule of thumb

Members after a VACE_FIELD() line are public until the next access specifier. Start a fresh private: block after the last editable field if you keep private state.

Logging

Five printf-style helpers, each mapping to a level in the editor console:

example 
void OnUpdate(float dt) override
{
    LogInfo("frame dt = %.4f", dt);

    if (GetNodeId() == 0)
    {
        LogWarning("script not attached to a node");
    }
}

Transform

Self transform

Convenience wrappers that read and write the transform of the node the script is attached to.

Vec3 GetPosition() const SetPosition(const Vec3&) const Quat GetRotation() const SetRotation(const Quat&) const Vec3 GetScale() const SetScale(const Vec3&) const
example

Scene scripts

When nodeId == 0 (a scene-level script, not attached to a node), all self-transform getters return defaults and all setters are no-ops. Guard with IsAttachedToNode() or use the targeted versions below.

Targeted transform

Read and write the transform of any node, addressed by its node id.

example 
std::uint32_t target = FindNodeByName("Enemy");
if (target != 0)
{
    SetNodePosition(target, Vec3(0.0f, 0.0f, -5.0f));
}

2D transform

For sprites and 2D scenes, use the 2D-aware accessors. Rotation is in radians (positive is counter-clockwise). Scale is a per-axis glm::vec2.

float GetRotation2D() const SetRotation2D(float radians) const glm::vec2 GetScale2D() const SetScale2D(const glm::vec2&) const float GetNodeRotation2D(std::uint32_t) const SetNodeRotation2D(std::uint32_t, float) const glm::vec2 GetNodeScale2D(std::uint32_t) const SetNodeScale2D(std::uint32_t, const glm::vec2&) const
example

// flip a sprite
SetScale2D(glm::vec2(-1.0f, 1.0f));

Scene loading

LoadScene is deferred: it queues a scene change for the end of the frame so the currently-running script finishes cleanly. The path is relative to the project root; the .vscene extension is optional.

bool LoadScene(const char* scenePath) const
example 
if (GetPosition().y < -100.0f)
{
    LoadScene("Scenes/GameOver.vscene");
}

Time

float GetTime() const

Seconds since the runtime started. Monotonic, unaffected by frame pacing.

Collision events

Physics events are collected per frame. Query them once per update. Each event identifies the two nodes in the contact, whether the contact started or ended, and whether either side is a trigger.

std::vector<ScriptCollision> GetCollisions(std::uint32_t nodeId, bool entered) const std::vector<ScriptCollision> GetCollisionsEntered() const std::vector<ScriptCollision> GetCollisionsExited() const
example 
for (const auto& c : GetCollisionsEntered())
{
    if (c.isTrigger)   // e.g. hit a pickup
    {
        LogInfo("picked up node %u", c.other);
        DestroyNode(c.other);
    }
}

Save data (JSON I/O)

Persistent key/value storage backed by JSON files. The host owns all parsing. You pass a file path (relative to the project root) and a dotted key like player.health or inventory.items[0].qty. Each write reads the file, mutates one path, and writes it back atomically.

bool SaveFloat(const char* path, const char* key, float) const float LoadFloat(const char* path, const char* key, float fallback = 0.0f) const bool SaveInt(const char* path, const char* key, int) const int LoadInt(const char* path, const char* key, int fallback = 0) const bool SaveBool(const char* path, const char* key, bool) const bool LoadBool(const char* path, const char* key, bool fallback = false) const bool SaveString(const char* path, const char* key, const std::string&) const std::string LoadString(const char* path, const char* key, const std::string& fallback = "") const bool DeleteKey(const char* path, const char* key) const bool KeyExists(const char* path, const char* key) const
example 
void OnCreate() override
{
    float hp = LoadFloat("saves/player.json", "player.health", 100.0f);
    LogInfo("loaded health = %.1f", hp);
}

void OnDestroy() override
{
    SaveFloat("saves/player.json", "player.health", 100.0f);
    SaveString("saves/player.json", "player.name", "Hero");
}
